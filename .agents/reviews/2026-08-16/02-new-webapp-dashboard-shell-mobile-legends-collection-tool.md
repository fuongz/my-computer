# Review: New webapp: dashboard shell + Mobile Legends collection tool

**How to review:** flip `- [ ]` to `- [x]` for each item you agree with; add a `> note` under any you don't. Implementation starts only after every box is `[x]`.

## Context

A second workspace, `apps/webapp`: TanStack Start + Vite + Tailwind v4 + shadcn (Base UI, `base-rhea`) + zustand, deployed as a Cloudflare Worker. It is a **dashboard of tools**, the same shape the extension's popup has — a registry of tool definitions, one route each — rather than a single-purpose app.

The scaffold is not invented. `apps/web` existed at `fc7a7ac` on exactly this stack and was removed in `ba544db` along with the backend; its `vite.config.ts` plugin order, the `#/*` two-declaration alias rule, `src/lib/theme.ts`'s pre-paint script and `src/styles/app.css`'s token block are restored verbatim. What is **not** restored is everything that made it a backend client: no Better Auth, no D1, no R2, no drizzle, no `server/`. The monorepo stays backend-free, and `wrangler.jsonc` has no bindings at all.

The first tool is **Bộ sưu tập Mobile Legends** — which heroes and which skins the user owns. The catalogue comes from the MLBB Fandom wiki's Lua data modules: 133 heroes with role, lane, region, release date and unlock price, and 1007 skins with tier, tag, availability and price.

D1–D4 were answered by the user before the card was written. D7–D9 arrived mid-implementation, also from the user; D7 reverses part of D4, and D9 removes work that had already been done and had passed — both recorded rather than quietly folded in.

## Decisions

- [x] **D1.** **Catalogue is a committed JSON dataset**, generated by `bun run --cwd apps/webapp data:sync` from the wiki's Lua modules. Offline, instant, re-run when a patch lands. (Rejected: proxying the wiki at runtime — every cold start would depend on Fandom, and the Lua parse would run on the Worker.) *(recommended)*
- [x] **D2.** **Owned state is browser-local**: zustand `persist` to `localStorage`, plus JSON export/import so it can move between devices. No account, no database — the repo dropped its backend in `ba544db` and this does not bring it back. *(recommended)*
- [x] **D3.** **The interface is Vietnamese**, matching the game client. Hero names, skin names, tiers and tags stay English — the wiki carries no Vietnamese ones, and inventing them would produce names no player could search for. *(recommended)*
- [x] **D4.** ~~Artwork is hotlinked from `static.wikia.nocookie.net`~~ — **superseded by D7**. Shipped this way first; the resolved CDN paths the sync script bakes into the dataset are now the download source rather than the `src`.
- [x] **D5.** **Ownership of a hero and of its skins are tracked independently.** Owning `Layla (Twilight Waltz)` does not mark Layla owned and does not require it — the game lets a skin sit in a collection for a hero you have not unlocked, and a UI that silently corrected that would be lying about the user's account. D8 is what this decision buys.
- [x] **D6.** **The dashboard is a registry, not a hardcoded nav.** `src/tools/registry.ts` holds `{ id, name, description, icon, to }` and both the sidebar and the landing page render from it, so tool #2 is one entry plus one route.
- [x] **D7.** **Every picture is downloaded into `public/mlbb/` and served by this app** — 1007 WebP files at 320px, 19 MB, named after the catalogue row's id so `images.ts` needs no lookup table and the dataset needs no extra field. `data:sync` calls `data:art` at the end so the two cannot drift. Costs 19 MB of third-party art in the repo; buys a page that does not depend on Fandom staying up, does not leak a visit to them per tile, and works offline in dev.
- [x] **D8.** **A panel names the heroes you own a skin for but have not unlocked.** Derived, never stored — it is the one thing the two sets in D5 can say that neither says alone, and the game's own collection screen will not tell you. Hidden entirely when the answer is none.
- [x] **D9.** **No automated browser check ships.** One was written and passed 20 assertions (both routes, the toggle, the reload, three filters, the derived panel, the dark theme) — the finding that the tiles needed their own `data-slot` because the filter chips are `aria-pressed` toggles too came out of it. The user reviews the app themselves, so `scripts/preview-mlbb.ts` and `.preview/` were deleted. The `data-slot` stays: it is right regardless of who is counting tiles.

## Out of scope

- Accounts, login, D1, R2 — the app is static plus localStorage.
- Vietnamese translations of hero and skin names.
- Emblems, battle spells, equipment, Magic Chess — heroes and skins only.
- Any write back to the game or to Moonton's servers. The app never talks to the game; the user marks ownership by hand.
- A second tool. The registry is built so one can be added, but only the MLBB tool ships here.
